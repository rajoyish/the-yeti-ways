# Create panel images and 3x2 timed grids

This is step 2 of the pipeline in section 7 of `.agents/rules/cinematic-direction.md`. The storyboard holds the video prompts and nothing else: every 10-second video is one table, three shots, and two beats in each shot's `Action:`. This skill writes every image prompt the film needs into one file next to the storyboard, and then builds the images from it in a fixed order:

1. The panel images: six prompts per video, one per beat, each drawing that beat's picture as a full single image with every lock in it. They show each beat at full size, and the six of them, with the family reference image, are the seven images the panel route attaches to the clip.
2. The grid: one horizontal 1920x1080 image per video that lays those same six panel images out three across and two down, with each panel's number, timecode, and title in a black strip above it. `compose_grid.ps1` builds it from the saved panel image files. It is never generated by an image model and it has no prompt.

The order is the point. An image model asked to draw six panels in one picture draws six new pictures: it changes the characters, the framing, and the light from the panel images, adds or drops panels, repeats labels, and lays the rows out wrong. A grid composed from the panel image files is those files, pixel for pixel, so the two routes in Flow show the model the same six pictures.

Google Flow takes at most seven ingredient images for one clip. Six panels per video is what lets every beat of the clip go in as its own image, with the family reference image as the seventh. No panel image and no grid is a start or an end frame.

The mapping is fixed, and it is the same for every video:

- Six panel images and one grid per video. A 30-second storyboard gives 18 panel images and three grids, and a 60-second storyboard 36 panel images and six grids. Never more and never fewer.
- Six panels per video, exactly, in reading order: panels 1, 2, and 3 across the top row of the grid and panels 4, 5, and 6 across the bottom row. Panels 1 and 2 are Shot 1, panels 3 and 4 are Shot 2, and panels 5 and 6 are Shot 3. Within a shot, the first panel is its first beat and the second panel its second beat.
- One beat per panel. A panel never merges two beats, never splits one, and never crosses the cut between two shots, so the six panels are six distinct pictures.
- Grid panel P is panel image P, scaled to fit its cell. Nothing is redrawn.
- The panel images are in the film's aspect ratio: 9:16 for the vertical Yeti shorts, 16:9 for a widescreen film. The grid is always a 1920x1080 horizontal canvas, whatever the film's shape.

The panel timecodes and framings come from the panel map in section 6 of `cinematic-direction.md`. How the character locks and the other locked pieces sit in a panel image prompt comes from sections 2 and 3 of `.agents/rules/prompt-assembly.md`, and the locks themselves from `.agents/rules/character-consistency.md`. All three files bind, and they win over this one wherever they disagree.

The storyboard never holds an image prompt, and this file never holds a video prompt. The storyboard's agent instructions send the operator here for the images each clip is generated with, and this file's intro says how to generate, check, and compose them.

## Image names

Every image for a film goes in `3x2-timed-storyboard-images/<slug>/`, named by panel and video number only, so a name never changes when a video's title does:

| Image | Name | Example |
| --- | --- | --- |
| Panel image P of Video N | `Panel_<P>_V<N>.jpg` | `Panel_1_V1.jpg`, `Panel_6_V3.jpg` |
| The grid of Video N | `Grid_V<N>.jpg` | `Grid_V2.jpg` |

`V` stands for the video number. Never use a title, a space, or a generic name such as `video_1.jpg`. The `Image:` and `Grid image:` lines in the 3x2 file give each path, and `compose_grid.ps1` and `check_grid.mjs` read those lines, so an image saved under any other name is not found.

## Rules that always apply

Read `.agents/rules/character-consistency.md` in full (the default; never `character-consistency-alt.md` unless the user asks for it by name), `.agents/rules/prompt-assembly.md` in full, `.agents/rules/cinematic-direction.md` (sections 1, 2, 4, and 6), and the "Rules that always apply" section of the skill that wrote the storyboard (`storyboard-30s-extender` or `storyboard-60s-from-story`). Every rule there about horns, looks, faces, energy, humans, animals, brands, and text applies to a panel image.

- The storyboard is the single source. Every panel's picture, face, framing, light, and effects comes from the storyboard's table for that video. Never invent a beat, a light, or a framing that the storyboard does not hold. If a panel cannot be drawn from the storyboard, fix the storyboard first, then write its panel images.
- Copy, never retype. The aspect ratio line, the style lock, the `Environment:` sentence, the `Lighting:` sentences, the supporting cast sentences, and the avoid line are copied from the storyboard character for character, and each character lock from the storyboard's `Character locks:` block, which is itself a copy of `character-consistency.md`. Every panel image is a fresh generation, so each one carries the full lock of every Yeti in it; nothing is shortened for a close-up or a wide. The fixed sentences below are copied from this file.
- One `Environment:` sentence per video. A video never changes location partway through, so its six panel images share one.
- Each panel image opens with the storyboard's own aspect ratio line: `Create image: Vertical 9:16 aspect ratio, full-frame vertical composition.` for the vertical Yeti shorts, and `Create image: Horizontal 16:9 aspect ratio, full-frame widescreen composition.` for a widescreen film.
- Faces follow the beats, as step 2 sets out. No smile of any kind on a beat of danger, worry, effort, sadness, or loss.
- No quality words that fight the locks. "Photorealistic", "hyperreal", "8K", or a named render engine, studio, or film look contradicts the style lock, the character locks, and the avoid line, and a named product or look trips the copyright filter.
- Each panel image is a single still of its panel, with the pieces in the still order of section 2 of `prompt-assembly.md`: the style lock, the `Environment:` sentence, its shot's `Lighting:` sentence, the full character lock of each Yeti in that panel and no other, the `Expressions:` sentence, the supporting cast sentences, and the avoid line. A Yeti who is in the shot but not in the panel gets no lock, because a lock for an absent Yeti puts that Yeti on screen.
- The `Expressions:` sentence holds the face the panel's beat gives each Yeti in it (step 2), so panel images 2, 4, and 6 carry the shot's own `Expressions:` values and panel images 1, 3, and 5 carry the faces of their beats.
- The Yetis are placed as the panel's picture places them, in the still form of section 3 of `prompt-assembly.md`: the lock alone for one Yeti, `On the left, <lock> On the right, <lock>` for two, and `On the left, <lock> In the center, <lock> On the right, <lock>` for three, left to right in the same order as the `Expressions:` sentence. A panel with no Yeti carries the no-Yeti sentence below where the locks would go, and no `Expressions:` sentence.
- The `Action:` opens with the panel's framing and angle and the word "still" (`Medium Shot, High Angle still.`) and describes the panel's picture as one held instant: present tense, one pose per character, eye lines stated, no "then" and no "begins to".
- Absence is stated, never implied. The `Action:` names every Yeti and every supporting character from the storyboard who is not in the picture, because an image model draws every character the prompt describes unless told not to.
- Counts are stated. When the picture holds several of one supporting animal or person ("the three grey wolves"), the `Action:` gives the number, and the supporting cast sentence says "exactly".
- The `Effects:` sentence holds only the effects from the shot's `Effects:` text that are visible at the panel's instant, frozen as section 6 of `cinematic-direction.md` describes. An effect that belongs to the shot's second beat (a crack that has not opened yet, spray from a run that has not started) stays out of its first panel. Leave the sentence out when no effect is visible.
- No text in any panel image: no number, timecode, title, caption, sign, logo, or watermark. The only text in the whole pipeline is the label strip `compose_grid.ps1` draws above each grid cell, outside the picture.
- Titles are two to four words in capitals, distinct within a video, and name the picture ("THE LOST KIT", "ICE SPLITS", "FAMILY HUDDLE"). They are the labels `compose_grid.ps1` prints on the grid.

## Fixed panel image sentences

Copy these word for word into every panel image prompt. `check_grid.mjs` reads them from this section, so change them here and nowhere else.

No-Yeti sentence, in place of the character locks when the panel has no Yeti:
"No Yeti is in this image."

Closing sentence, the last sentence of every panel image prompt:
"Single still reference image. No text, captions, or watermark."

## Grid layout

`compose_grid.ps1` holds the layout, so change it there and nowhere else. It is fixed for every film:

- Canvas: 1920x1080 pixels, horizontal, black, saved as a JPEG.
- Cells: three across and two down, each 640x540, read left to right and top to bottom, panels 1 to 3 on the top row and 4 to 6 on the bottom row.
- Label strip: the top of each cell, black, holding `<P> · <timecode> · <TITLE>` in small, clean white letters. No other text anywhere.
- Picture: the panel image scaled to fit the rest of the cell without cropping or stretching, centred on black, with a thin black border around it. A vertical 9:16 panel image sits in the middle of its cell with black on each side.

## Workflow

### 1. Get the storyboard

The input is `prompts/<slug>-30s-storyboard.md` or `prompts/<slug>-60s-storyboard.md`, as a path. Read it in full, including the agent instructions and every lock paragraph.

- If the user gives a short storyboard, a story, or a source storyboard instead, stop and name step 1: `/storyboard-30s-extender` or `/storyboard-60s-from-story`. Do not write the storyboard and the image prompts in one run; a single run that writes both runs past a model's output limit.
- If the storyboard predates the character locks (it has no `Character locks:` block above its tables, or its cells carry an `[EXPRESSION]` slot or a `Head lock:`, `Look lock:`, or `Scale lock:` sentence), revise it first with step 6 of `storyboard-30s-extender` or step 8 of `storyboard-60s-from-story`, save it, and tell the user.
- If the storyboard still has `Frames:`, `Start frame:`, `Midpoint frame:`, `End frame:`, `Grid:`, or `Stills:` lines, an `Action:` that is not two sentences (a storyboard written for the old 3x3 grid has three), agent instructions that name a `-3x3.md` file or panel images 3, 6, and 9, or agent instructions that say how to generate or check images, it predates the current format. Revise it first with step 6 of `storyboard-30s-extender` or step 8 of `storyboard-60s-from-story`, save it, and tell the user.
- Run the storyboard skill's own checklist on the file. Every panel image is copied from it, so an image prompt written against a storyboard that later changes is wrong.
- Carry the storyboard's image-side notes into this file's intro: which characters and props may appear in which panels, a likely image filter trigger, and any image made before the storyboard last changed that has to be regenerated.

The slug is the storyboard's filename without `-30s-storyboard.md` or `-60s-storyboard.md`. The length is `30s` or `60s`, from the same filename.

An older 3x2 file needs revising before it is used, in any of these forms:

- It holds a grid prompt: a code block under each video heading, before the first panel image, that opens `Create image: Horizontal 16:9` and has `Shot` and `Panel` lines with `Faces:` lists. Delete the grid prompt, the grid's `Image:` line, and the layout, reference, and quality sentences it carried. Keep its titles: each panel heading's title becomes that panel's title in capitals. Add the `Grid image:` line from the template.
- Its `Image:` lines name `Video N - <Title> - Panel P.jpg` or `Video N - <Title>.jpg`. Rewrite each to `Panel_<P>_V<N>.jpg`, and rename any saved panel image on disk to match (`git mv` if the images are tracked, a plain move if they are ignored). Move any grid an image model drew to a `_superseded/` folder beside the images rather than using it; compose the grid again in step 7.
- Its panel image prompts carry the older character text with an `[EXPRESSION]` slot and `Head lock:`, `Look lock:`, or `Scale lock:` sentences. Rewrite each prompt as section 9 of `prompt-assembly.md` sets out: the placed full locks in place of the character text, the slot values moved into an `Expressions:` sentence, the three lock sentences deleted, and the Yetis in the `Action:` renamed from colour to name. Regenerate any panel image that fails the look check against the current locks, and compose its grid again.
- It is a `-3x3.md` file from the nine-panel grid. Rename it to `-3x2.md` with `git mv` and rewrite it; never keep both.

### 2. Map each video to six panels

For each `## Video N - <Title>` in the storyboard, in order, walk its three table rows and split each `Action:` into its two sentences. Write down, for each of the six panels:

- Panel number (1 to 6), timecode, and shot, from the panel map in section 6 of `cinematic-direction.md`:

  | Panel | Place in the grid | Shot | Beat | Timecode |
  | --- | --- | --- | --- | --- |
  | 1, 2 | Top left, top centre | Shot 1 (`00:00–00:03`) | 1st, 2nd sentence of Shot 1's `Action:` | `00:00.0–00:01.5`, `00:01.5–00:03.0` |
  | 3, 4 | Top right, bottom left | Shot 2 (`00:03–00:07`) | 1st, 2nd sentence of Shot 2's `Action:` | `00:03.0–00:05.0`, `00:05.0–00:07.0` |
  | 5, 6 | Bottom centre, bottom right | Shot 3 (`00:07–00:10`) | 1st, 2nd sentence of Shot 3's `Action:` | `00:07.0–00:08.5`, `00:08.5–00:10.0` |

- The framing and angle, from the shot's Shot Type cell: the opening framing in the shot's first panel and the closing framing in its second, as section 6 of `cinematic-direction.md` sets out. A shot that holds its framing uses it in both.
- The picture: the beat sentence frozen at the end of its beat, as one held image. Where each character is in the panel, what each paw holds, where each eye line points, and which Yetis, humans, and animals are in it and which are not. Present tense, one pose per character, no "then" and no "begins to". Name each Yeti by name.
- The face of each Yeti in the panel, as a row from the section 4 table of `prompt-assembly.md`:
  - Panels 2, 4, and 6: that Yeti's face in the shot's `Expressions:` sentence, copied.
  - Panels 1, 3, and 5: the row that matches the feeling the beat names for that Yeti. When the beat names none, the Yeti keeps the face it had in the panel before. For panel 1 of Video 1, that is Shot 1's `Expressions:` value; for panel 1 of any later video, it is the previous video's Shot 3 `Expressions:` value, because the handoff keeps the face. A Yeti who enters in a beat that names no feeling takes its shot's `Expressions:` value.
  - At the Climax peak (panel 3 of Video 2 in a 30-second film, panel 6 of Video 3 in a 60-second film), the face is the peak feeling the beat names.
- The shot's `Lighting:` sentence, copied. If the shot changes the light in its first beat, the first panel's picture says the change is under way.
- The shot's effects: its `Effects:` text frozen, as section 6 of `cinematic-direction.md` describes, and for each panel the part of it that is visible at that instant. Leave it out when the shot has `Effects: None.`
- A title for the panel.

Then check the mapping before writing a word of prompt:

- Six panels, two per shot, every beat used once.
- The six pictures are distinct. Two panels that describe the same picture mean two beats in the storyboard say the same thing; fix the storyboard, not the panels.
- Panel 1 of each video after the first shows the same picture as panel 6 of the video before, in its own framing, unless the video is marked `Scene break:`.
- Every Yeti in a panel is named in its shot's `Characters:` sentence and has a lock in its video's `Character locks:` block. A panel that shows a Yeti its storyboard shot leaves out, or a shot whose `Characters:` sentence names a Yeti its `Action:` says is not there, means the storyboard is wrong; fix it first.

### 3. Write the panel image prompts

For each video, write its six panel images in order. Each one is a level-3 heading, an `Image:` line, and one fenced code block holding the prompt as a single paragraph.

Heading, with the panel's timecode, framing, angle, and title in capitals:

```
### Panel <P> · <timecode> · <Framing>, <Angle> · <TITLE>
```

Image line, naming where the generated image is saved:

```
Image: `3x2-timed-storyboard-images/<slug>/Panel_<P>_V<N>.jpg`.
```

Prompt order inside the code block:

1. `Create image:` and the storyboard's aspect ratio line, on one line.
2. The style lock.
3. The `Environment:` sentence.
4. The shot's `Lighting:` sentence.
5. The full character lock of each Yeti in the panel, placed, or the no-Yeti sentence.
6. The `Expressions:` sentence with each placed Yeti's face, in the same order, if the panel has a Yeti.
7. The storyboard's `Humans:`, `Animals:`, or `Creatures:` sentences, if it has them.
8. The avoid line.
9. `Action:` `<Framing>, <Angle> still.` and the panel's picture as a held instant, ending with who is not in it.
10. `Effects:` the shot's effects visible at this instant, frozen, if any are.
11. The closing sentence.

### 4. Write the file

Save to `prompts/<slug>-<30s or 60s>-3x2.md`, next to the storyboard. Use the template below. The `## Video N - <Title>` headings are the storyboard's, word for word, so every file in the pipeline names each video the same way. Under each heading come the `Film position:`, `Stage:`, `Video prompt:`, and `Grid image:` lines, and then the six panel images. There is no grid prompt. Never write into the storyboard.

If the model's output limit is near, write and save one video at a time, appending to the file, and run the checker once all of them are in.

### 5. Verify the prompts before generating

Run the checker with Node:

```
node .agents/skills/create-3x2-timed-image/check_grid.mjs prompts/<slug>-<30s or 60s>-3x2.md
```

It finds the storyboard by name and checks both files. For the storyboard: no start or end frame lines, no `Grid:` or `Stills:` lines, no `Create image:` prompt, no mention of the old 3x3 grid, and none of the older character text or head, look, or scale lock sentences; a `Character locks:` block above every table holding, word for word, the lock of every Yeti the video's `Characters:` sentences name; three rows per table on the fixed split; a `Characters:` or no-Yeti sentence and a matching `Expressions:` sentence in every cell, with faces from the section 4 table; two sentences in every `Action:`; and no shot whose `Characters:` sentence names a Yeti its `Action:` says is not in it. For each video: the heading matches the storyboard's; the `Grid image:` line names `Grid_V<N>.jpg`; there is no grid prompt; there are exactly six panel images, in order, each heading timed to the panel map, framed against its shot, and titled in capitals with a title of its own; each `Image:` line names `Panel_<P>_V<N>.jpg`; each prompt carries the storyboard's aspect ratio line, the style lock, the `Environment:` sentence, the shot's `Lighting:` sentence word for word, the full character lock of exactly the Yetis its shot allows, placed in the still form, or the no-Yeti sentence; an `Expressions:` sentence naming the same Yetis in the same order with faces from the section 4 table; the supporting cast and avoid line word for word; the `Action:` opener; the closing sentence; all of it in order; and the faces in panels 2, 4, and 6 equal to the shot's `Expressions:` sentence. The six pictures must be distinct. It prints `OK` or the problems for each video and exits with status 1 if anything fails. Fix every problem and run it again until every video prints `OK`. It also prints `Note:` lines for things to look at that are not always wrong, such as a panel 1 face that differs from the panel 6 face before it.

Then check what the script cannot:

- [ ] Every panel's picture is the beat it comes from, frozen at the end of the beat, with no motion words, and it agrees with the faces in its `Expressions:` sentence.
- [ ] Every Yeti in a picture is named by name and placed in the panel, on the side its lock is placed, and no picture puts a paw or prop on or above a Yeti's head.
- [ ] Every panel's picture agrees with the character locks: paws, not hands, nothing worn, and Babu Yeti about half as tall as a grown-up Yeti beside him.
- [ ] Panel 1 of each video after the first shows the same picture as panel 6 of the video before, unless the video is marked `Scene break:`.
- [ ] Every `Effects:` sentence holds the shot's own effects, frozen, visible at that instant, none from a later beat, and nothing a Yeti gives off.
- [ ] Every `Action:` states which Yetis and supporting characters are not in the picture, and gives the number of any group of animals or people in it.
- [ ] Titles are two to four words, in capitals, and name the picture.

### 6. Generate the panel images

Generate only when the user asks for images, or ran the skill to get them. The family reference image is needed for this step; if the user has not attached it, ask for it now and wait.

For each video, in order, generate its six panel images one at a time, before its grid:

1. Generate the panel image with the image tool (`generate_image` in Antigravity, or Google Flow): the prompt is the panel's whole code block, the family reference image is attached as a character reference, the output is set to the film's aspect ratio, and `ImageName` is `Panel_<P>_V<N>`.
2. Check it against its prompt: the film's aspect ratio, the picture, faces, framing, and light the prompt names, every listed character present and no one else (count any group), no text in it, and the look check in section 7 of `prompt-assembly.md`. Regenerate it if it fails.
3. Save it to the path its `Image:` line names, `3x2-timed-storyboard-images/<slug>/Panel_<P>_V<N>.jpg`. Create the folder if it does not exist. Never use a generic name.
4. Once all six are saved, look at them side by side. Each Yeti must be recognisably the same individual in every panel, as the Final Consistency Checklist in `character-consistency.md` sets out: the three read as distinct individuals, not one model in three colours, with no colour, tuft, face, build, or scale traded between them, and every supporting character the same too (the same clothes, the same animal, the same colours), and panel 1 must match panel 6 of the video before. Regenerate any image that breaks the set.

If the session has no image tool, stop after step 5 and tell the user how to generate the panel images in Google Flow: set the output to the film's aspect ratio, attach the family reference image, paste one panel prompt at a time, whole, run the checks above, and save each image under the name its `Image:` line gives. Then they run step 7 themselves, or ask for it.

### 7. Compose the grids

When a video's six panel images are saved and checked, compose its grid from them. Never generate a grid with an image model, and never edit a grid by hand. Run, from the repository root:

```
pwsh -File .agents/skills/create-3x2-timed-image/compose_grid.ps1 -File prompts/<slug>-<30s or 60s>-3x2.md
```

It reads each video's six panel headings and `Image:` lines from the 3x2 file, loads the six panel image files, and writes the 1920x1080 grid to the path the video's `Grid image:` line names, with each panel's number, timecode, and title in the strip above it. `-Video <N>` composes one video only. It stops without writing a grid when any of the six panel images is missing, and warns when a panel image is not in the film's aspect ratio. Whenever a panel image is regenerated, compose its video's grid again, so the grid always holds the current panel images.

Then confirm it with the checker's image mode, which checks that every panel image exists, that every grid exists, is 1920x1080, and is newer than all six of its panel images:

```
node .agents/skills/create-3x2-timed-image/check_grid.mjs prompts/<slug>-<30s or 60s>-3x2.md --images
```

### 8. Report

Tell the user the file path, the number of panel images and grids, and which images were generated, saved, and composed. Name the next step: the storyboard's agent instructions, which generate each 10-second clip in Flow from its table with the video's six panel images and the family reference image attached, or its composed grid and the family reference image.
