# Create panel images and 3x2 timed grids

This is step 2 of the pipeline in section 7 of `.agents/rules/cinematic-direction.md`. The storyboard holds the video prompts and nothing else: every 10-second video is one `Agent prompt:` block whose shot lines cover six beats on a fixed clock, cut into three to six shots of one or two beats each. This skill writes the image prompts the film needs into one file next to the storyboard, and then builds the images from it in a fixed order:

1. The panel images: six prompts per video, one per beat, each drawing that beat's picture as a full single image with every lock in it. They show each beat at full size, and the six of them, with the Yeti reference images, are what each clip is guided by and checked against.
2. The grid: one horizontal 1920x1080 image per video that lays those same six panel images out three across and two down, with each panel's number, timecode, and title in a black strip above it. `compose_grid.ps1` builds it from the saved panel image files. It is never generated by an image model and it has no prompt.

The order is the point. An image model asked to draw six panels in one picture draws six new pictures: it changes the characters, the framing, and the light from the panel images, adds or drops panels, repeats labels, and lays the rows out wrong. A grid composed from the panel image files is those files, pixel for pixel, so the grid shows exactly the six checked pictures.

In Google Flow (`.agents/rules/google-flow.md`) the clip takes its identity from the saved Characters and its place from a plate or an opening frame; a panel image is attached only as a composition guide, one at a time, and a grid never.

The mapping is fixed, and it is the same for every video:

- Six panel images and one grid per video in the file.
- Six panels per video, exactly, in reading order: panels 1, 2, and 3 across the top row of the grid and panels 4, 5, and 6 across the bottom row. Panel P is beat P of the video, wherever the cuts fall: walk the shot lines in order and give each as many panels as it has beats (one or two). A two-beat shot's first panel is its first beat and its second panel its second beat; a one-beat shot is one panel.
- One beat per panel. A panel never merges two beats, never splits one, and never crosses the cut between two shots, so the six panels are six distinct pictures.
- Grid panel P is panel image P, scaled to fit its cell. Nothing is redrawn.
- The panel images are in the film's aspect ratio: 9:16 for the vertical Yeti shorts, 16:9 for a widescreen film. The grid is always a 1920x1080 horizontal canvas, whatever the film's shape.

The panel timecodes and framings come from the panel map in section 6 of `cinematic-direction.md`. How the character locks and the other pieces sit in a panel image prompt comes from sections 2 and 3 of `.agents/rules/prompt-assembly.md`, and the locks themselves from `.agents/rules/character-consistency.md`. All three files bind, and they win over this one wherever they disagree.

The storyboard never holds an image prompt, and this file never holds a video prompt.

## Image names

Every image for a film goes in `3x2-timed-storyboard-images/<slug>/`, named by panel and video number only, so a name never changes when a video's title does:

| Image | Name | Example |
| --- | --- | --- |
| Panel image P of Video N | `Panel_<P>_V<N>.jpg` | `Panel_1_V1.jpg`, `Panel_6_V3.jpg` |
| The grid of Video N | `Grid_V<N>.jpg` | `Grid_V2.jpg` |

`V` stands for the video number. Never use a title, a space, or a generic name such as `video_1.jpg`. The `Image:` and `Grid image:` lines in the 3x2 file give each path, and `compose_grid.ps1` and `check_grid.mjs` read those lines, so an image saved under any other name is not found.

## Reading an Agent prompt

Each `## Video N - <Title>` section of the storyboard holds one `Agent prompt:` block. The pieces a panel image needs come from it like this, and `check_grid.mjs` derives them the same way:

| Panel image piece | Taken from the Agent prompt |
| --- | --- |
| Aspect ratio line | The format line: `Vertical 9:16 video` gives `Vertical 9:16 aspect ratio, full-frame vertical composition.`, `Horizontal 16:9 video` gives `Horizontal 16:9 aspect ratio, full-frame widescreen composition.` |
| Style lock | The format line, word for word (it is the lock in section 1 of `prompt-assembly.md`). |
| `Environment:` sentence | `Environment: ` and the `Setting:` line's text, word for word. One per video. |
| Shot | One shot line: `<start>-<end>, <Framing> (<cut>)[ to <Framing> (<cut>)], <Angle>[ to <Angle>]. In frame: <list>. <beats, camera, Effects:>. Light: <light>.` |
| `Lighting:` sentence | `Lighting: ` and the shot line's `Light:` text, word for word, with its first letter in capitals. |
| `In frame:` sentence | The shot line's `In frame: ...` sentence, word for word. |
| Yetis in the panel | The Yetis the `In frame:` sentence names. |
| Faces | The rows of the section 4 table of `prompt-assembly.md` that the shot line uses. A shot's closing face is the last one in its line. |
| Story cast sentences | For each non-Yeti character the `In frame:` sentence names: the "Full, for still image prompts" sentence in its file in `prompts/characters/` (`<kebab-case name>-flow-character.md`), word for word; with no file, the description in the `Cast:` line, written as a `Humans:`, `Animals:`, or `Creatures:` sentence. |
| Effects | The shot line's `Effects:` text, frozen. |
| Beats | Each shot covers one or two beats by its timestamps (`00:00`, `00:01.5`, `00:03`, `00:05`, `00:07`, `00:08.5`, `00:10`). Split its action into the beats by what happens first and what happens last. |

A shot line that does not parse this way, or a video whose shots do not run from `00:00` to `00:10` on the beat boundaries, is a storyboard problem: fix the storyboard with its skill first.

## Rules that always apply

Read `.agents/rules/character-consistency.md` in full (the default; never `character-consistency-alt.md` unless the user asks for it by name), `.agents/rules/prompt-assembly.md` in full, `.agents/rules/cinematic-direction.md` (sections 1, 2, 4, and 6), and the "Rules that always apply" section of the skill that wrote the storyboard (`storyboard-30s` or `storyboard-60s`). Every rule there about horns, looks, faces, energy, humans, animals, brands, and text applies to a panel image.

- The storyboard is the single source. Every panel's picture, face, framing, light, and effects comes from its video's Agent prompt. Never invent a beat, a light, or a framing the Agent prompt does not hold. If a panel cannot be drawn from it, fix the storyboard first, then write its panel images.
- Yeti reference images. Every panel image is generated with the saved front image of each Yeti in it attached as a character reference (`references/characters/<papa, mama, or babu>-yeti-front.png` or `.jpg`, the same images as the Flow Characters; fall back to the canonical portrait `<name>-yeti.png` if a front image is not saved yet), plus `references/characters/family-height-chart.png` whenever Babu Yeti shares the panel with a grown-up. Never attach the front image of a Yeti who is not in the panel. If none of these files exist, ask the user for them before generating.
- An opening frame named on the Agent prompt's first line (`Open on the image ...`) is never attached to a panel image. It may have drifted, and a panel image is checked against the locks, not against a frame.
- Copy, never retype. The aspect ratio line, the style lock, the `Environment:` and `Lighting:` sentences, the `In frame:` sentence, the story cast sentences, and the avoid line are copied as the table above sets out, character for character, and each character lock straight from the `text` block in `character-consistency.md`. Every panel image is a fresh generation, so each one carries the full lock of every Yeti in it; nothing is shortened for a close-up or a wide.
- One `Environment:` sentence per video.
- No quality words that fight the locks. "Photorealistic", "hyperreal", "8K", or a named render engine, studio, or film look contradicts the style lock, the character locks, and the avoid line, and a named product or look trips the copyright filter.
- Each panel image is a single still of its panel, with the pieces in the still order of section 2 of `prompt-assembly.md`: `Create image:` and the aspect ratio line, the style lock, the `Environment:` sentence, its shot's `Lighting:` sentence, the full character lock of each Yeti in that panel and no other, the `Expressions:` sentence, the story cast sentences, the shot's `In frame:` sentence, the avoid line, `Action:`, `Effects:`, and the closing sentence. A Yeti who is in the shot but not visible in the panel (a hands-only Extreme Close-Up still shows the Yeti's hands, so it keeps the lock) gets no lock only when the shot's `In frame:` sentence does not name it.
- The `Expressions:` sentence holds the face the panel's beat gives each Yeti in it: a panel that is its shot's last beat carries the shot's closing face; the first panel of a two-beat shot carries the face of its beat. A panel where the Yeti's face is out of frame (a hands-only Extreme Close-Up) still carries the shot's face, so the hands and posture agree with it.
- The Yetis are placed as the panel's picture places them, in the still form of section 3 of `prompt-assembly.md`: the lock alone for one Yeti, `On the left, <lock> On the right, <lock>` for two, and `On the left, <lock> In the center, <lock> On the right, <lock>` for three, left to right in the same order as the `Expressions:` sentence. A panel with no Yeti carries the no-Yeti sentence below where the locks would go, and no `Expressions:` sentence.
- The `Action:` opens with the panel's framing and angle and the word "still" (`Medium Shot, High Angle still.`) and describes the panel's picture as one held instant: present tense, one pose per character, eye lines stated, no "then" and no "begins to". Yeti hands that do something visible are "five-fingered hands", feet are "five-toed feet", never paws.
- Only who is in frame. The panel describes and names only the characters its shot's `In frame:` sentence names, and never names a character to say it is absent.
- Counts are stated. When the picture holds several of one supporting animal or person, the `Action:` gives the number, and the story cast sentence says "exactly".
- The `Effects:` sentence holds only the effects from the shot's `Effects:` text that are visible at the panel's instant, frozen, as section 6 of `cinematic-direction.md` describes. Leave it out when no effect is visible.
- No text in any panel image: no number, timecode, title, caption, sign, logo, or watermark. The only text in the whole pipeline is the label strip `compose_grid.ps1` draws above each grid cell, outside the picture.
- Titles are two to four words in capitals, distinct within a video, and name the picture ("THE LOST KIT", "ICE SPLITS", "FAMILY HUDDLE"). They are the labels `compose_grid.ps1` prints on the grid.
- A storyboard note about a filter trigger (Instruction 2's "Recorded trigger") applies to the panel prompts too: keep the same wording out of them.

## Fixed panel image sentences

Copy these word for word into every panel image prompt. `check_grid.mjs` reads them from this section, so change them here and nowhere else.

No-Yeti sentence, in place of the character locks when the panel has no Yeti:
"No Yeti is in this image."

Closing sentence, the last sentence of every panel image prompt:
"Single still reference image. No text, captions, or watermark."

## Grid layout

`compose_grid.ps1` holds the layout, so change it there and nowhere else. It is fixed for every film:

- Canvas: 1920x1080 pixels, horizontal, black, saved as a JPEG.
- Cells: three across and two down, each 640x540, read left to right and top to bottom, panels 1 to 3 on the top row and 4 to 6 on the bottom row.
- Label strip: the top of each cell, black, holding `<P> · <timecode> · <TITLE>` in small, clean white letters. No other text anywhere.
- Picture: the panel image scaled to fit the rest of the cell without cropping or stretching, centred on black, with a thin black border around it. A vertical 9:16 panel image sits in the middle of its cell with black on each side.

## Workflow

### 1. Get the storyboard

The input is `prompts/<slug>-<length>-storyboard.md`, as a path, and optionally the videos to cover ("Video 6 only"). Read it in full, including the Agent instruction cards: Instruction 2 holds the film's light, music, cast, and any recorded filter trigger.

- If the user gives a short storyboard, a story, or a source storyboard instead, stop and name step 1: `/storyboard-30s` or `/storyboard-60s`. Do not write the storyboard and the image prompts in one run.
- If the storyboard is in the older table format (it has `| Timestamp | Shot Type |` tables), it predates the current format: revise it with step 6 of `storyboard-30s` or step 8 of `storyboard-60s` first, save it, and tell the user. The table-reading version of this skill is kept in `.agents/backups/2026-10-31-table-storyboards/`.
- Carry the storyboard's image-side notes into this file's intro: which characters and props may appear in which panels, a likely image filter trigger, and any image made before the storyboard last changed that has to be regenerated.

The slug and length come from the storyboard's filename (`<slug>-<length>-storyboard.md`), and the 3x2 file is `prompts/<slug>-<length>-3x2.md`. When the user names only some videos, the 3x2 file holds only those, under their storyboard headings; when it already exists, replace those videos' sections in it and keep the others.

### 2. Map each video to six panels

For each video to cover, walk its shot lines in order. Write down, for each of the six panels:

- Panel number (1 to 6), timecode, and shot, from the panel map in section 6 of `cinematic-direction.md`:

  | Panel | Place in the grid | Beat | Timecode |
  | --- | --- | --- | --- |
  | 1 | Top left | 1 | `00:00.0–00:01.5` |
  | 2 | Top centre | 2 | `00:01.5–00:03.0` |
  | 3 | Top right | 3 | `00:03.0–00:05.0` |
  | 4 | Bottom left | 4 | `00:05.0–00:07.0` |
  | 5 | Bottom centre | 5 | `00:07.0–00:08.5` |
  | 6 | Bottom right | 6 | `00:08.5–00:10.0` |

  Each panel belongs to the shot whose timestamp holds its timecode.

- The framing and angle, from the shot line: a one-beat shot's single framing; for a two-beat shot whose framing changes (`<A> (..) to <B> (..)`), the first framing in its first panel and the second in its second, and the same for an angle that changes (`High Angle to Bird's-Eye View`). A shot that holds its framing uses it in both.
- The picture: the beat frozen at the end of its beat, as one held image. Where each character is in the panel, what each hand holds, where each eye line points. Present tense, one pose per character. Name each Yeti by name. A panel 1 whose video opens on a frame (`Open on the image ...`) and whose shot says "Matching the opening image" draws the picture the shot line describes, not the frame.
- The face of each Yeti in the panel, as a row from the section 4 table of `prompt-assembly.md`, as the rules above set out.
- The shot's `Lighting:` sentence, as the table above sets out.
- The shot's effects visible at the panel's instant, frozen.
- A title for the panel.

Then check the mapping before writing a word of prompt:

- Six panels, every beat used once, and six distinct pictures. Two panels that describe the same picture mean two beats in the storyboard say the same thing; fix the storyboard, not the panels.
- Panel 1 of each video after the first shows the same picture as panel 6 of the video before, in its own framing, unless the video has a `Scene break:` line or opens on a frame other than the previous end frame.

### 3. Write the panel image prompts

For each video, write its six panel images in order. Each one is a level-3 heading, an `Image:` line, and one fenced code block holding the prompt as a single paragraph.

Heading, with the panel's timecode, framing, angle, and title in capitals:

```
### Panel <P> · <timecode> · <Framing>, <Angle> · <TITLE>
```

Image line:

```
Image: `3x2-timed-storyboard-images/<slug>/Panel_<P>_V<N>.jpg`.
```

Prompt order inside the code block:

1. `Create image:` and the aspect ratio line, on one line.
2. The style lock.
3. The `Environment:` sentence.
4. The shot's `Lighting:` sentence.
5. The full character lock of each Yeti in the panel, placed, or the no-Yeti sentence.
6. The `Expressions:` sentence with each placed Yeti's face, in the same order, if the panel has a Yeti.
7. The story cast sentences of the characters in the panel, if any.
8. The shot's `In frame:` sentence.
9. The avoid line.
10. `Action:` `<Framing>, <Angle> still.` and the panel's picture as a held instant.
11. `Effects:` the shot's effects visible at this instant, frozen, if any are.
12. The closing sentence.

### 4. Write the file

Save to `prompts/<slug>-<length>-3x2.md`, next to the storyboard. Use the template below. The `## Video N - <Title>` headings are the storyboard's, word for word. Under each heading come the `Film position:`, `Video prompt:`, and `Grid image:` lines, and then the six panel images. There is no grid prompt. Never write into the storyboard.

If the model's output limit is near, write and save one video at a time, appending to the file, and run the checker once all of them are in.

### 5. Verify the prompts before generating

```
node .agents/skills/create-3x2-timed-image/check_grid.mjs prompts/<slug>-<length>-3x2.md
```

It finds the storyboard by name, reads every video's Agent prompt as the table under "Reading an Agent prompt" sets out, and checks each video in the 3x2 file against its own: the heading matches a storyboard video; the `Grid image:` line names `Grid_V<N>.jpg`; there is no grid prompt; there are exactly six panel images, in order, each heading timed to the panel map, framed and angled as its shot, and titled in capitals with a title of its own; each `Image:` line names `Panel_<P>_V<N>.jpg`; each prompt carries the aspect ratio line, the style lock, the `Environment:` sentence, the shot's `Lighting:` sentence and `In frame:` sentence word for word, the full character lock of exactly the Yetis the shot's `In frame:` names, placed in the still form, or the no-Yeti sentence; an `Expressions:` sentence naming the same Yetis in the same order with faces from the section 4 table, and the shot's closing face on the shot's last panel; the story cast sentences from `prompts/characters/` word for word; the avoid line; the `Action:` opener; the closing sentence; all of it in order. The six pictures must be distinct. It prints `OK` or the problems for each video and exits with status 1 if anything fails. Fix every problem and run it again until every video prints `OK`. It also prints `Note:` lines for things to look at that are not always wrong.

Then check what the script cannot:

- [ ] Every panel's picture is the beat it comes from, frozen at the end of the beat, with no motion words, and it agrees with the faces in its `Expressions:` sentence.
- [ ] Every Yeti in a picture is named by name and placed in the panel, and no picture puts a hand or prop on or above a Yeti's head.
- [ ] Every Yeti hand that does something visible is a "five-fingered hand", every foot a "five-toed foot", and nothing calls them paws.
- [ ] Every `Effects:` sentence holds the shot's own effects, frozen, visible at that instant, none from a later beat, and nothing a Yeti gives off.
- [ ] No wording from a recorded filter trigger in the storyboard's Instruction 2.
- [ ] Titles are two to four words, in capitals, and name the picture.

### 6. Generate the panel images

Generate only when the user asks for images, or ran the skill to get them. The Yeti reference images are needed for this step; if they are not in `references/characters/` and the user has not attached them, ask for them now and wait.

For each video, in order, generate its six panel images one at a time, before its grid:

1. Generate the panel image with the image tool (Nano Banana Pro in Google Flow): the prompt is the panel's whole code block, the Yeti reference images are attached as character references, the output is set to the film's aspect ratio, and the image is named `Panel_<P>_V<N>`.
2. Check it against its prompt: the film's aspect ratio, the picture, faces, framing, and light the prompt names, every listed character present and no one else (count any group), no text in it, and the look check in section 7 of `prompt-assembly.md`. Regenerate it if it fails.
3. Save it to the path its `Image:` line names. Create the folder if it does not exist.
4. Once all six are saved, look at them side by side. Each Yeti must be recognisably the same individual in every panel, as the Final Consistency Checklist in `character-consistency.md` sets out. Regenerate any image that breaks the set.

If the session has no image tool, stop after step 5 and tell the user how to generate the panel images in Google Flow: set the output to the film's aspect ratio, attach the Yeti reference images, paste one panel prompt at a time, whole, run the checks above, and save each image under the name its `Image:` line gives.

### 7. Compose the grids

When a video's six panel images are saved and checked, compose its grid from them. Never generate a grid with an image model, and never edit a grid by hand. From the repository root:

```
pwsh -File .agents/skills/create-3x2-timed-image/compose_grid.ps1 -File prompts/<slug>-<length>-3x2.md -Video <N>
```

It reads the video's six panel headings and `Image:` lines, loads the six panel image files, and writes the 1920x1080 grid to the path the `Grid image:` line names. It stops without writing a grid when any of the six panel images is missing. Whenever a panel image is regenerated, compose its video's grid again. Then confirm it:

```
node .agents/skills/create-3x2-timed-image/check_grid.mjs prompts/<slug>-<length>-3x2.md --images
```

### 8. Report

Tell the user the file path, the videos and panel images it holds, and which images were generated, saved, and composed. Name the next steps: `/generate-triptych-prompts` for the drawn 1x3 review sheets, and in Flow, at most one single panel image as a composition guide for a hard beat. The grids and triptychs are for review and are never attached to a clip.
